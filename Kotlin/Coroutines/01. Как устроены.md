# Как устроены корутины

### Что такое корутины?
Корутины - это механизм для написания асинхронного кода в последовательном стиле, без использования колбэков.
Корутины позволяют выполнять длительные операции конкурентно, не блокируя поток, если используемая операция действительно является неблокирующей.

### Чем корутина отличается от потока?
Корутина - это лёгкая единица работы, которая выполняется внутри потока. Она может приостанавливаться и возобновляться, не блокирую поток, и при этом занимает очень мало ресурсов.
В одном потоке может выполняться тысячи корутин одновременно. Поток же - это тяжелый системный объект операционной системы, создание и переключение между потоками, требует заметных ресурсов, и их количество ограничено.

### Что такое `suspend` функции?
`suspend` функция - это функция, которая может быть приостановлена во время выполнения и возобновлена позже без блокировки потока. Тем самым позволяя выполнять длительные операции, не замораживая основной поток приложения.
Вызов suspend функций возможен только из корутин или другой suspend функции.

### Что такое `Continuation`?
Continuation — Интерфейс, который позволяет возобновить выполнение с результатом или ошибкой через resumeWith().

``` kotlin
interface Continuation<in T> {
    val context: CoroutineContext
    fun resumeWith(result: Result<T>)
}
```

### Жизненный цикл корутин
Корутина проходит через несколько состояний в течение своего жизненного цикла:

| **#** | **Цикл**          | **Описание**                                                                                                       |
|-------|-------------------|--------------------------------------------------------------------------------------------------------------------|
| 1     | **Создание**      | Корутина создается с помощью билдера, такого как `launch` или async                                                |
| 2     | **Запуск**        | Корутина начинает выполнение, когда её запускают с помощью `start()` или автоматически, если используется `launch` |
| 3     | **Приостановка**  | Корутина может быть приостановлена при вызове suspend-функции, например, `delay()` или `await()`                   |
| 4     | **Возобновление** | После завершения асинхронной операции корутина возобновляет выполнение с места приостановки                        |
| 5     | **Завершение**    | Корутина завершает выполнение, когда весь код внутри неё выполнен или когда она отменена                           |

### Как корутины работают под капотом?

#### Ключевые компоненты

| **#** | **Компонент**                                     | **Описание**                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
|-------|---------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 1     | **StandaloneCoroutine**                           | Объект, создаваемый реализацией `launch`. Он представляет корутину на уровне `kotlinx.coroutines`, управляет её жизненным циклом и возвращается из `launch` как `Job`. Его родитель `AbstractCoroutine` реализует интерфейсы: `Job`, `Continuation<Unit>` и `CoroutineScope`.                                                                                                                                                                                      |
| 2     | **Сгенерированный класс лямбды со стейт-машиной** | Для suspend-лямбды, переданной в `launch`, компилятор генерирует класс, который обычно наследуется от `SuspendLambda` и реализует `Function2<CoroutineScope, Continuation<Unit>, Object>` на JVM с учётом стирания типов.<br/>Этот класс содержит: <br/>`invoke()` — точку входа при вызове лямбды как функции <br/>`create()` — создание экземпляра продолжения для конкретного вызова <br/>`invokeSuspend()` — реализацию тела лямбды в виде конечного автомата. |
| 3     | **Continuation**                                  | Интерфейс, который позволяет возобновить выполнение с результатом или ошибкой через resumeWith(). Конкретный объект продолжения хранит или обеспечивает доступ к состоянию, необходимому для продолжения выполнения. <br/>В сгенерированной state machine это, например, label и сохранённые локальные переменные.                                                                                                                                                      |
| 4     | **COROUTINE_SUSPENDED**                           | Специальный маркер, показывающий, что suspend-вызов не завершился обычным возвратом, а приостановил выполнение и продолжится позже.                                                                                                                                                                                                                                                                                                                                                                       |

#### Последовательность выполнения
**1. Вызов launch**

Создаёт объект корутины `StandaloneCoroutine`, который представляет её жизненный цикл и доступен вызывающему коду через `Job`.



**2. Передача блока корутины**

В `launch` передаётся сгенерированный объект suspend-лямбды. Его класс наследуется от `SuspendLambda` и содержит реализацию стейт-машины.



**3. Запуск блока**

В обычном сценарии библиотека запускает блок через механизм продолжений. Вызов `invoke()` создаёт или получает экземпляр продолжения для данного выполнения и вызывает `invokeSuspend(Unit)`.



**4. Выполнение state machine**

`invokeSuspend()` выполняет код в соответствии с `label`. При `label = 0` выполняется начальный участок — в нашем примере до вызова `delay()`.



**5. Приостановка**

Перед вызовом `delay()` компилятор устанавливает следующее состояние. Если после ожидания нужно восстановить локальные переменные, он сохраняет их. Если вызов возвращает `COROUTINE_SUSPENDED`, текущий `invokeSuspend()` тоже возвращает этот маркер.



**6. Возобновление**

Когда операция готова продолжиться, соответствующий механизм возобновляет `Continuation` через `resumeWith(result)`. Продолжение запускается снова, теперь с результатом возобновления и сохранённым состоянием.



**7. Продолжение и завершение**

`invokeSuspend()` определяет по `label`, с какого участка продолжить выполнение. Когда всё тело завершено, результат передаётся по цепочке продолжений, а `StandaloneCoroutine` фиксирует завершение корутины и её жизненного цикла.

#### Код под капотом

Пример кода в котором создается корутина и вызываются suspend функции.

``` kotlin
class KotlinCoroutines {

    fun main() {
        CoroutineScope(context = EmptyCoroutineContext).launch {
            val file: File = download(url = "site.ru")
            val size: String = size(file = file)

            println("Файл $file размером $size загружен")
        }
    }
}
```

Возобновление suspend функции и передача результата происходит через `it.resumeWith(result)`

``` kotlin
suspendCancellableCoroutine { 
    it.resumeWith(result = Result.success(value = "COMPLETED!")) 
}
```
