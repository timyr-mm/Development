# ЧЕРНОВИК

Когда мы создаем корутину scope.launch {...}, происходит следующее:

- Создается StandaloneCoroutine при вызове функции launch {...} и возвращается из нее как Job. StandaloneCoroutine унаследует класс AbstractCoroutine, который в свою очередь реализует Job, Continuation и CoroutineScope. Те по сути этот класс является корутиной.

- Компилятор генерирует класс для каждой корутины создаваемой через launch { ... }. Сгенерированный класс наследуется от SuspendLambda и реализует Function2<CoroutineScope, Continuation, Object>.

2. Внутри сгенерированного класса находится сгенерированная реализация метода invokeSuspend(Object result) из иерархии BaseContinuationImpl (родитель SuspendLambda) со стейт-машиной, а также invoke(CoroutineScope p1, Continuation p2) из Function2, который создает новый Continuation с передачей в него Continuation и запускает invokeSuspend()





3. Первым при обычном запуске launch {...} вызывается метод invoke() из Function2, потому что передаваемый в launch блок имеет тип suspend CoroutineScope.() -> Unit. 


В сгенерированном классе вызывается метод invoke(CoroutineScope p1, Continuation p2), в который передается 





4. invoke() создаёт/получает экземпляр state machine и вызывает invokeSuspend(Unit).

5. В invokeSuspend() все точки приостановки (suspend) представлены состояниями state machine. Переключение между состояниями происходит с помощью int label.

6. Сначала выполняется состояние с label = 0. В нём выполняется код до первой точки приостановки. Перед вызовом suspend-функции компилятор сохраняет необходимые локальные переменные, устанавливает следующее значение label и передаёт текущий Continuation как completion.

7. Если вызываемая suspend-функция приостанавливается, она возвращает специальный маркер COROUTINE_SUSPENDED. Тогда вызывающий invokeSuspend() тоже возвращает COROUTINE_SUSPENDED, и выполнение корутины на этом останавливается.

8. Когда операция, вызвавшая приостановку, готова продолжить корутину, она вызывает resumeWith(result) у Continuation. Через цепочку completion управление возвращается в continuation вызывающей корутины.

9. Вызывающая state machine снова входит в invokeSuspend(), но уже с новым значением label, поэтому switch позволяет продолжить выполнение с нужного места.

10. Этот процесс повторяется для каждой точки приостановки, пока вся корутина не выполнится и не вернёт финальный результат.

11. Результат **возобновления** suspend-функции передаётся через Continuation.resumeWith(result). Например, внутри suspendCancellableCoroutine { ... } можно вручную возобновить корутину: it.resumeWith(Result.success("COMPLETED!")).

# Как устроены корутины

### Что такое корутины?
Корутины - это механизм для написания асинхронного кода в последовательном стиле, без использования колбэков.
Корутины позволяют выполнять длительные операции конкурентно, не блокируя поток, если используемая операция действительно является неблокирующей.

### Чем корутина отличается от потока?
Корутина - это лёгкая единица работы, которая выполняется внутри потока. Она может приостанавливаться и возобновляться, не блокирую поток, и при этом занимает очень мало ресурсов.
В одном потоке может выполняться тысячи корутин одновременно. Поток же - это тяжелый системный объект операционной системы, создание и переключение между потоками, требует заметных ресурсов, и их количество ограничено.

### Что такое `suspend` функции?
`suspend` функция - это функция, которая может быть приостановлена во время выполнения и возобновлена позже без блокировки потока. Тем самым позволяя выполнять длительные операции, не замораживая основной поток приложения.
Вызов suspend функций возможен только из корутин или другой suspend функции.

### Что такое `Continuation`?
Continuation — представляет собой объект, через который можно продолжить выполнение с определённого места и передать результат возобновления.

В Kotlin Continuation — это интерфейс, который выглядит следующим образом:
``` kotlin
interface Continuation<in T> {
    val context: CoroutineContext
    fun resumeWith(result: Result<T>)
}
```

### Жизненный цикл корутин
Корутина проходит через несколько состояний в течение своего жизненного цикла:

1. **Создание:** Корутина создается с помощью билдера, такого как launch или async.

2. **Запуск:** Корутина начинает выполнение, когда её запускают с помощью start() или автоматически, если используется launch.

3. **Приостановка:** Корутина может быть приостановлена при вызове suspend-функции, например, delay() или await().

4. **Возобновление:** После завершения асинхронной операции корутина возобновляет выполнение с места приостановки.

5. **Завершение:** Корутина завершает выполнение, когда весь код внутри неё выполнен или когда она отменена.

#### Код под капотом

Пример кода в котором создается корутина и вызываются suspend функции.

``` kotlin
class KotlinCoroutines {

    fun main() {
        CoroutineScope(context = EmptyCoroutineContext).launch {
            val file: File = download(url = "site.ru")
            val size: String = size(file = file)

            println("Файл $file размером $size загружен")
        }
    }
}
```

``` java
}
```
